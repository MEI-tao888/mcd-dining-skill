# 规则只筛选，JEV 做判断

> ⚠️ 2026-10-24 A6.1 起：JEV 回退档废止；JEV 为必需裁判，失败不给方案。

- **规则**只做硬筛选：预算、忌口、门店营业、取餐方式、商品可售；**不做加权评分、不做排序**。
- 候选保留 2–3 组，且类型有差异（稳妥 / 轻 / 奖励），但都合法、都在预算内。
- **JEV** 在 2–3 组里做最后判断：`choice` 选一组、`score` 评"合不合此刻"、`boolean` 安全闸门；用 `confidence` 决定是否再聊一句。
- ~~JEV 不可用 / 超时 / 低置信：走**安全默认**（最稳、最便宜或最熟悉的一组）~~ —— **已废止（见顶部）**。现行为：judge `exit 2`、`chosenId=null`，不给方案。

## 为什么

加权评分是伪精确：规则无法平衡"便宜 vs 合心情""熟悉 vs 新鲜"这类主观取舍。规则擅长排除不合适的，不擅长在都合适的里面挑一个；后者正是 JEV 的位置。

## 为什么不把 JEV 放到所有地方

JEV 只对 2–3 组已经合法的候选做一次判断，成本低、风险可控；门店/菜单/算价仍由 MCP 和脚本负责。

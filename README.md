# 简单麦 · Easy Eat

![小简 · 简单麦 Easy Eat](pet/assets/pet-pixel-render.png)

> **吃饭很重要，选饭可以很简单。**
> **Eat well. Choose easy.**
> 简单麦 Easy Eat：不填表、不比价、不纠结；聊两句，吃得刚刚好。
>
> 麦当劳程序员创意开发大赛 / WaytoAGI 1024 切磋大会「用餐」赛道 参赛作品

## 一句话介绍

吃饭很重要，选饭可以很简单。简单麦不给你菜单，也不让你填问卷：像饭搭子一样聊两句，它替你把门店、菜单、价格和券查清楚，只给你一份刚好合现在状态的套餐。

## 解决什么问题

1. 不想填问卷、不想回答一堆问题——点餐不该像做调查；
2. 不想在套餐/券/价格之间做复合选择——选项越多越焦虑；
3. 想吃得合状态（心情、累不累、赶不赶、预算），但不想把注意力花在“选”上。

**核心原则：只给一份；券服务于决定，不改变决定。**

### 它不做什么

- 不摊菜单、不给 A/B/C、不做“多选一”；
- 不比价、不做券组合优化；
- 不猜用户没说过的话；
- 不在 JEV 未就绪时给推荐；
- 不静默下单。

## 它怎么工作

1. **先聊**：读语气与状态，只问最自然的一两个问题；不填表、不摊选项；
2. **边聊边判断**：心情、能量、时间、预算、口味、饮食偏好；
3. **调 MCP**：履约（默认到店自取，也支持外送）→ 门店 → 菜单 → 候选 → 算价 → 门店券；
4. **硬筛到 2–3 组候选**：只做硬约束过滤，不做加权评分、不做排序；
5. **JEV 判断（必需）**：在 2–3 组里选“最合此刻”的一组；会话开始先查 JEV 健康，不通就不点餐；运行中失败/低置信也**不给方案**——不拿"规则推荐"顶替；
6. **只给一份** + 一句理由（引用用户自己的话）+ 一个“换”的出口。

## 先看这个：前置条件（四项缺一不可）

这个仓库**不是下载后就能出推荐**。要跑出一份推荐，下面四项都得就绪：

| # | 前置条件 | 缺了会怎样 | 怎么确认 |
|---|---|---|---|
| 1 | **麦当劳 MCP Token**（环境变量 `MCD_MCP_TOKEN`） | `mcp.mjs` / `candidates.mjs` 直接报错，查不到门店和菜单 | 见下方「1. 申请麦当劳 MCP Token」 |
| 2 | **JEV key**（环境变量 `JEVMODEL_API_KEY`，或本机文件 `%USERPROFILE%\.jevmodel\api_key.txt`） | `judge.mjs` exit 2，**不推荐** | `node scripts/judge.mjs --health` |
| 3 | **可用的海外出口**（访问 JEV 服务 `jevmodel.org`） | JEV 在中国大陆直连会被拒（HTTP 451，见 ADR 0006）；`judge.mjs` 默认走本机代理 `http://127.0.0.1:7897`，可用 `JEV_PROXY` 改 | 同上，`--health` 返回 `provider: "jev"` 才算通 |
| 4 | **Node.js 22+** | 脚本是 ESM `.mjs`，低版本不保证能跑 | `node -v` |

**JEV 未就绪 → 不推荐。** 这是设计，不是故障：没有 JEV 的判断，就不给方案，也不会用规则打分顶替。`judge.mjs --health` 不通时，先修前置条件，再来点餐。

## 快速开始

### 一键安装（Windows）

下载仓库后，双击：

```text
install-easy-eat.cmd
```

安装器会检查 WorkBuddy / MCP Token / JEV Key，复制 Skill 和程序目录，并跑一次 JEV health。  
完整步骤见 [INSTALL.md](INSTALL.md)。

### 手动安装

#### 1. 申请麦当劳 MCP Token

前往 <https://open.mcd.cn/mcp>：手机号登录 → 控制台 → 激活 → 同意协议 → 复制 Token。

### 2. 配置 MCP

把 `mcp-config.example.json` 里的 `${MCD_MCP_TOKEN}` 换成你的真实 Token（**不要提交真实 Token**）。

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer ${MCD_MCP_TOKEN}" }
    }
  }
}
```

### 3. 在 WorkBuddy 里使用

- 在 WorkBuddy 项目根打开本仓库，加载 `skills/easy-eat/SKILL.md`；
- 设置环境变量 `MCD_MCP_TOKEN`；
- 直接说“午饭吃啥 / 饿了 / 随便”，它会先聊、再给一份。

本地脚本也可以直接跑（在 `meal-skill/` 根目录）：

```bash
# 到店自取
node scripts/candidates.mjs --mode pickup --city 武汉 --keyword 华中农业大学 \
  --store 1960216 --people 1 --budget 80 --coupons auto

# 外送（自动选营业门店）
node scripts/candidates.mjs --mode delivery --city 武汉 --keyword 华中农业大学 \
  --people 1 --budget 100 --coupons auto
```

### 4. JEV 判断（必需）

`judge.mjs` 会在 2–3 组候选里做最后判断。**JEV 是必需裁判**：无 key / 超时 / 451 → judge **exit 2**，不给方案；会话开始先跑 `judge.mjs --health`。key 只放环境变量或本机文件，不进仓库。需要的 key、海外出口和 Node 版本见上方「前置条件」。

## 可选：桌面小简

![小简待机 / 悬停 / 点击](pet/assets/pet-pixel-render.png)

`pet/` 里有一个 Windows 像素风小宠物，不参与推荐逻辑，只是入口：

- 双击 `pet/start-pet.cmd`；
- 第一次启动会显示三步新手教程：领 MCP Token、注册 JEV、检查是否配好；
- 点击小简 → 启动语进剪贴板 + 打开/激活 WorkBuddy；
- 到 WorkBuddy 里 Ctrl+V，开始和简单麦对话。

它只做启动器，不调 MCP、不调 JEV、不读 Token。没有它，Skill 也能正常用。

## 使用示例

> **用户**：午饭吃啥
> **简单麦**：看你这会儿还没吃。想吃扎实点，还是吃完还能干活？
> **用户**：干活
> **简单麦**：懂了，不能太撑。有没有不能碰的（过敏那种）？
> **用户**：没有
> **简单麦**：今天给你配“堡”你欢乐套餐，¥28.00——你说“吃完还能干活”，我就没配薯条那套，省得你下午犯困。不合适你说换。

示例价格 ¥28.00 是某次 `calculate-price` 返回的**快照**（对应 `data/candidates.json`），不是实时价；菜单与价格会随门店、时段变化，以你运行时的实时结果为准。

## 目标用户

注意力被工作、带娃或学习占满，**想吃得不差，但不想再为点餐做一次决策**的人。  
默认场景：工作日午餐 1–2 人；不是美食探索者，重点是“够好 + 不费神”。

## 边界与安全

- **履约范围**：默认**到店自取**；**外送（麦乐送）为第二模式**，外送不可用时改按到店自取，不虚构门店或地址。不承诺 ETA、不承诺库存。
- **可靠优先**：默认到店自取，只有用户明确说“送 / 外卖 / 到家”才走外送——“累”“不想动”不算。关于套餐内容、换品、饮料、价格、券、门店，只用 MCP 返回或用户原话，不说“能选的话 / 应该可以 / 可能”。
- **JEV 是必需裁判**：新会话先跑 `judge.mjs --health`；无 key / 超时 / 451 → judge **exit 2**，不给方案。judge 默认严格（不需要开关），拿不到 JEV 判断就 `chosenId=null`——**未就绪不能推荐**，也不降级成规则推荐。`--allow-fallback` 仅供离线排障。
- **过敏警告**：`--avoid` 只按菜单文字匹配；选定那一组后，`detail.mjs` 会再把已知过敏原和详情里**全部**的商品名、套餐选项、加减料名字比对一遍（命中就换组或避开）。但两道都只看**名字**，覆盖不到配料表、酱料与交叉接触，**不构成过敏安全保证**，没命中也只会说“只核对了菜名”，不会说“安全”；过敏状态未知时不核对。过敏请以门店与包装标注为准。
- **隐私**：地址只在内存中使用；仓库、日志与 `data/*.json` 只保存 `addressRef`，不保存 addressId、联系人、电话、完整地址。过敏信息只存本机 `memory/health.json`，可清空，不发送给 JEV。
- **发给 JEV 的内容（境外服务，经你的代理）**：只有 ① 对话摘要：心情 / 饱腹 / 口味 / 时间压力 / 新鲜感 / 人数 / 预算 / 取餐方式；② 最多 4 条**过滤后**的用户原话；③ 2–3 组候选的 id、类型、餐品名、价格、一句说明。**不发**：过敏与任何健康信息、地址与 `addressRef`、手机号、Token、门店编号。过滤规则：用户原话里含过敏 / 忌口 / 病史、门牌 / 地址、电话 / 邮箱的整句直接丢弃，不打码。可用 `node scripts/judge.mjs --candidates data/candidates.json --dry-run` 查看完整外发请求体（只打印，不发送；需要本机有 JEV key）。过滤是关键词规则，不保证覆盖所有说法，所以 SKILL 同时要求：这类内容一开始就不放进 `quotes`。
- **券**：只用于已经选中的那一份；没命中就按原价，不为用券换类型、加商品、改候选，也不编“券后价”。券码/券 ID 不落盘。
- **价格**：一律以 `calculate-price` 的权威返回为准；模型不做价格算术。
- **写操作**：领券、下单、取消订单必须由用户明确确认，本项目不静默执行。
